# 0.0.4: signed runs

Released 2026-09-17. Build notes: [docs/BUILD.md](../docs/BUILD.md#004-signed-runs).

## What shipped

- An Ed25519-signed manifest per run, `<run id>.attest.json`, written at run end, failed runs included. It holds the final hash, the event count, the schema version, the run id and the ledger file's SHA-256.
- `seatbelt keygen`, `seatbelt attest <ledger> --key`, and `seatbelt verify --pubkey`, which reports ATTESTED, FORGED, UNCHECKED or UNATTESTED.
- A truncated or rewritten tail, which the chain check alone accepts, is now detected.

## Plan vs what shipped

- The plan was Sigstore keyless signing, an in-toto Statement, `verify --signed`, and an HTML evidence report. What shipped is Ed25519 with a local key and a `--pubkey` flag. The evidence pack moved to 0.1.0.
- It is ADR 0002, not the planned ADR-0010.

## Worth studying

- The gap a hash chain leaves: drop the tail, append a fresh `run.end` with a matching count, and the chain verifies ([ADR 0001](../docs/adr/0001-hash-chained-jsonl-ledger.md), Consequences).
- Why HMAC was rejected (whoever can verify can forge), and why Sigstore was deferred (network at sign time, a heavy dependency) ([ADR 0002](../docs/adr/0002-signed-run-manifest.md)).
- The trust boundary. Attestation proves the ledger has not changed since run end by anyone without the key. It does not prove the process was honest ([ADR 0002](../docs/adr/0002-signed-run-manifest.md)).
- Why the verifier's own public key is used, and the one embedded in the manifest is never trusted.
