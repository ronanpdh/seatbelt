# 0.3.0: every major client, and recording with no gateway

Released 2026-09-29. Build notes: [docs/BUILD.md](../docs/BUILD.md#030-every-major-client-and-recording-with-no-gateway).

## What shipped

- The OpenAI Responses and Gemini `generateContent` formats, with `seatbelt run codex` and `seatbelt run gemini`.
- Local recording. `seatbelt run` starts the gateway inside the run, the CLI keeps its own sign-in, and each run is signed on the machine. `seatbelt runs` lists runs by name.
- Config reload on change or `SIGHUP`, OIDC sign-in for Claude Desktop, and a central sink to S3-compatible storage.
- `seatbelt import compliance`, for Claude Enterprise transcripts, tested against a fake of the documented API only.
- CodeQL, Hadolint, Atheris fuzzing, digest-pinned images, and the gateway image on GHCR with provenance.

## Plan vs what shipped

- The gateway design's 0.3.0 phase listed six items; all six shipped.
- Local recording was not in that list.
- The importer's scope narrowed from "Team and Enterprise" to Enterprise only.

## Worth studying

- Why local recording puts the run's key in the URL path, not a custom header: CLIs also send their custom headers to other hosts. Codex is the exception; it gets the key in its environment and sends it only to its model provider ([docs/local-recording.md](../docs/local-recording.md)).
- What an imported ledger attests. It says "this is what Anthropic's Compliance API returned when seatbelt asked", not "these bytes crossed the gateway" ([importer design](../docs/plans/2026-09-29-compliance-importer-design.md)).
- OIDC at the gateway: signature, `iss`, `aud` and `exp` checks, asymmetric algorithms only, and users keyed by the provider's immutable id.
- Fuzzing parsers so that they "must only refuse, never crash" (CHANGELOG 0.3.0).
- Which config fields reload live and which need a restart, and why a failed reload keeps the running config.
