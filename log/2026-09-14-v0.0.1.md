# 0.0.1: a run you can verify and reconstruct

Released 2026-09-14. Build notes: [docs/BUILD.md](../docs/BUILD.md#001-a-run-you-can-verify-and-reconstruct).

## What shipped

- An event model (`Event`, `Actor`, `Kind`) with canonical JSON hashing and a genesis hash.
- An append-only JSONL `Ledger` with a SHA-256 hash chain per run, which resumes after a restart.
- Redaction of common secret formats before anything is hashed or written.
- The `Recorder` API: run start and end (with a failure flag), user message, model call, tool call, policy check, decision (with authority and basis), action, and outcome.
- `verify_events` and `verify_file`, with a `Verdict` that names the first bad sequence number. Timeline reconstruction.
- The CLI: `seatbelt version`, `verify` (exit 1 on tamper), `reconstruct` and `demo`.
- Project scaffolding: uv, ruff, pyright strict, pytest, Hypothesis, pre-commit, CI, Dependabot, Scorecard, SECURITY.md, CONTRIBUTING.md, STANDARDS.md and ROADMAP.md.

## Plan vs what shipped

- The code in the build guide's v0.0.1 section shipped.
- The guide asked for six ADRs before coding. Four of their topics became [ADR 0001](../docs/adr/0001-hash-chained-jsonl-ledger.md). The other two, OpenTelemetry attribute names and kinds from the scope chain, live in the `Event` and `Kind` docstrings.
- The learning pathway had planned v0.0.1 (week 4) as the first slice of an adversarial harness: `Finding`, `Scenario` and `Target` models, one target adapter, and one hand-written prompt-injection scenario recording a `Finding`. The build guide put the audit layer first instead. Adapters came in 0.0.2, and scenarios in 0.1.0.

## Worth studying

- Canonical JSON: "Two processes serialising the same event must produce the same bytes or the chain is worthless" (build guide, step 2; `Event.canonical` in `src/seatbelt/ledger/events.py`).
- Redact before hash: "The provable record is the redacted one. Consequence: you cannot later prove what a secret was, only that one was present" (build guide, "Decisions to record as ADRs").
- What a hash chain alone does not catch: drop the tail, append a fresh `run.end` with a matching count, and the chain verifies ([ADR 0001](../docs/adr/0001-hash-chained-jsonl-ledger.md), Consequences; [ADR 0002](../docs/adr/0002-signed-run-manifest.md), Context). 0.0.2's INCOMPLETE status catches a plain truncation, but not this forgery. 0.0.4's signed manifest closes the gap when the reviewer verifies with the public key (`verify --pubkey`).
- Property-based testing: `test_editing_any_attr_breaks_the_chain` in `tests/unit/test_ledger.py` uses Hypothesis to substitute arbitrary non-empty strings for one attribute value (`outcome.summary`) of the second event, and asserts that verification then fails at seq 1.
